# HELLDIVER 主版本使用指南

## 1. 连接与开始

完整解压软件，保留 HELLDIVER_Main.exe 和 _internal 文件夹；不需要 Python、Node 或 DGHub。
选择游戏屏幕，再从“手机连接地址”选择与手机同一局域网的电脑网卡。点击“连接 APP”，用 DG-LAB APP 的 SOCKET 入口扫描本次二维码。二维码等待两分钟，超时后重新连接生成新码。

新增 HUD 档位适配针对 1920×1080、游戏画面完整铺满所选屏幕，建议无边框全屏。先在游戏中设置 HUD 大小，再到软件“HUD 设置”选择相同档位，无需重新框选。旧安装未选择新档位时仍使用旧版兼容预设；其既有 16:9 等比例换算行为不代表新增 HUD 模式支持其他分辨率。

进入地面战场后按 F8 开始，再按 F8 暂停。启动时 SAFE / OUTPUT LOCKED 是暂停状态；ARMED 表示启用。进入飞船、菜单前可先 F8 暂停。全局 ESC 留给游戏。
点击“停止全部”或关闭主窗口/控制窗结束会话。F8 暂停保留 APP 配对；停止全部会关闭本次后端，下次需重新扫码。

## 1.1 灵动岛悬浮窗

完整控制窗左下角的 ISLAND [-] 按钮可折叠为屏幕上方的圆角小胶囊。它显示 PAUSED（暂停）、LIVE（正在识别）或 NO HUD（当前画面无有效血条）；无有效血条时 HP 显示 --，不把拒识当成零血。

## 1.1.1 遥遥领先风格界面

左侧导航包含任务控制、反馈设置、HUD 设置、截图检查、使用指南和连接权限。任务控制直接显示连接与五类反馈配置；反馈设置页使用同一份编辑内容，不会产生两份不同的草稿。离开反馈编辑区、开始会话或关闭程序时，如有修改会询问保存、放弃或取消。保存失败不会启动会话。

电路与点阵仅作装饰。顶部“待机电弧动画”可关闭，单独保存在 EXE 旁的 ui_settings.ini。默认只在任务控制待机时缓慢变化亮度；会话启动（包括 F8 暂停）、截图检查、权限操作、最小化时停止动画。控制窗和灵动岛始终静态。界面设置损坏回退为静态，不影响识别或连接。

底部的 A/B 是软件最近成功提交的强度，不是 APP 或实体设备读回值；Mock 模式是本地合成值。HP 使用现有显示血量。没有有效 HUD 或暂停时显示 HP --；状态超过一秒未更新，显示“状态更新中断”和未知输出，不把陈旧值伪装成实时归零。会话结束后的未知输出也不等于设备端确认。

小窗口或较大 Windows 字体缩放下内容可滚动，停止全部始终位于底部。Windows 显示缩放与游戏 HUD 档位无关。日志可从左下角展开，不会替代原会话日志文件。新版仍使用 Windows 原生标题栏，不向游戏注入界面。

胶囊的三角形／暂停图标与 F8 一样用于启停，最右侧小窗图标展开回完整控制窗。折叠／展开不改变当前启停状态，不重新连接 APP。每次新会话从完整面板开始。

鼠标悬停不会自动展开或启用；置顶、悬停、按钮点击及折叠均使用不激活窗口的处理，避免抢走游戏焦点。仍建议使用无边框全屏；不向游戏注入覆盖层，不保证独占全屏下可见。关闭整个程序仍用主窗口的停止全部，或展开后关闭控制窗。

按钮必须在内部按下并松开才响应；按住拖出按钮会取消本次点击，移回来也不会恢复。展开时恢复完整面板原位置，并限制在显示器可见工作区。暂停时显示 HP --；正在识别但没有有效 HUD 时，两种布局都显示 HP -- / NO HUD。

首次测试建议先点“仅测试识别”：保持游戏或截图窗口在前台，移动鼠标经过悬浮窗，反复折叠／展开，再用 F8 和胶囊按钮启停，确认游戏没有切出。桌面替身窗口测试不等于实际游戏验收；不同显示器和 Windows 缩放仍需对应环境核对，不要为测试改动系统安全设置。

## 1.2 HUD 大小与截图检查

这里选择的是游戏 HUD 大小，不是分辨率或 Windows 缩放。主窗口“HUD 设置”提供 0.75、0.80、0.85、0.90、0.95、1.00、1.05、1.10、1.15、1.20、1.25 共 11 档，每档准确增加 0.05。请和游戏菜单保持一致；软件不会替你修改游戏设置或自动切换档位。

0.75–1.00 及 1.25 标为“已有满血实拍”，1.05–1.20 标为“插值推算”。前者表示已有真实截图支持定位，后者表示根据两端档位推算位置和大小；这些来源说明不代表每档的残血、治疗、死亡或真实手机输出都已经通过实机验收。像素必须取整，相邻档位的像素增加量可能差 1 个像素。

点击“保存设置”，设置保存到 EXE 旁的 hud_settings.ini，在下次启动会话时生效。只有“停止全部”后可以修改，F8 暂停不解锁。首次升级未保存 HUD 设置时显示“旧版兼容预设，尚未选择 HUD 档位”，保留旧版配置；不把旧坐标默认当成 1.00。

“截图检查”在停止状态下选择本地原图，无需扫码、连接 APP 或开启后端。它显示图片实际尺寸、血条放大图、端帽及测量框、单帧血量估计和拒识原因。新 HUD 模式要求 1920×1080，错误尺寸会明确提示，不会先缩放图片。应使用原始完整截图，不裁剪、不缩放；1919×1079 等近似尺寸也不当作 1920×1080。

推荐先用同档位的满血和残血原图做截图检查，再点“仅测试识别”测试游戏实时画面。单张图片只检查当前血量；受伤、治疗、死亡和持续反馈需要连续画面。检测到错误档位、遮挡或 HUD 消失时停止两路输出并显示 NO HUD / HP --，重新识别到 HUD 后建立新基线，不凭空补发伤害或治疗。

游戏中需要换 HUD 大小时，先按 F8 暂停，再点“停止全部”，修改游戏设置和软件档位后重新启动。所选屏幕尺寸变化或配置损坏时软件会阻止启动，请修正尺寸或重新保存合法档位。新 HUD 模式的当前范围是 1080p 与现有血条布局，尚未验证的游戏视角、窗口留边或其他分辨率需另行适配。

## 2. 波形与 A/B 设置

“残血／濒死触发血量”允许 0–100 的整数百分比，每次 1%，默认 75%。确认有效基线后，0＜有效血量＜所选门槛时持续反馈；等于门槛就退出残血层。100% 在满血时也不触发。0% 只关闭残血持续反馈，不关闭受伤、治疗或死亡，不清空原 A/B 数值。这是血量门槛，不是输出强度；A/B 共用门槛，强度仍独立。

门槛保存在 EXE 旁 feedback_settings.ini 的 [trigger] low_health_threshold_percent 中；旧文件缺此项默认 75%，不会自动重写。只修改强度不会重置门槛。只有“停止全部”后可修改，保存后下次会话生效，F8 暂停不解锁。“恢复默认”会填回 75%，仍需保存。识别使用有效原始血量，不用显示平滑值；无 HUD 不当作零血量。

主窗口点“反馈设置”。通道模式为仅 A、仅 B、A+B；默认仅 A。双通道共用波形和事件节奏，但 A/B 强度及总上限分别设置。未启用通道不会输出，数值仍保留。

五类反馈各有波形下拉选项、A 强度、B 强度：

- 受伤反馈：0.2 秒窗口累计掉血；默认官方“连击”，基准 A/B=20。
- 残血／濒死：默认 0＜血量＜75% 时持续，门槛可调，0% 关闭；默认官方“呼吸”，A/B=10。不新增另一套重伤事件。
- 治疗确认：有效血量回升时的确认脉冲；默认官方“潮汐”，A/B=15。
- 治疗持续舒缓：回血期间保持，并在最近一次回血后继续 2 秒；默认原治疗模板，A/B=5。
- 死亡：连续有效血量由正数归零，一条生命只触发一次；默认原死亡模板，A/B=40。

受伤和治疗确认默认持续 2 秒，死亡默认 5 秒；这些是事件持续时间，不是波形模板的长度。模板可以循环，到事件结束时切换/停止，并清理未播放队列。识别无效或暂停会提前停止。

复活时，连续有效识别到的回血沿用治疗反馈；HUD 消失后重新建立基线，不凭空补发治疗。满血稳定不新增反馈，但刚回血到满血仍会完成尚未结束的确认与舒缓。

波形选择优先级：死亡 > 治疗确认 > 受伤 > 治疗舒缓 > 残血。死亡清除其他层。其他有效反馈的强度可以叠加，每条通道最终只播放当前优先波形。某条通道强度为 0 时该条停止；两路都没有强度贡献的事件不会抢占波形。

“受伤强度”是基准而非每次固定输出。例如设置 20，窗口累计掉血 20%，伤害贡献为 4；若同时有残血 10，该路合成为 14，再由该路总上限限制。最小正伤害保留 1 个强度单位；基准设为 0 则不贡献。

界面强度与上限范围为整数 0–100，各路总上限默认 100。这些是软件输出单位，不是百分比或体感保证。APP 还可能施加自身通道上限；软件配置值、叠加结果、APP 当前显示值不一定相同。波形模板内部的幅度包络也会影响 APP 波形显示。

选择波形后点击“保存设置”；“恢复默认”只填回默认值，仍需保存。关闭窗口不保存未确认改动。设置在 EXE 旁的 feedback_settings.ini 中，下次打开自动读取。
只能“停止全部”后修改并在下次连接生效，F8 暂停不解锁设置。运行中设置只读，指南仍可查看。设置损坏时连接被阻止，请打开设置检查并保存，程序不会带着未知参数启动。

## 3. 波形库

内置官方 16 组 V3 示例，包括呼吸、潮汐、连击、心跳节奏等；加上原治疗与死亡模板，总共 18 个可选项。呼吸与原弱脉冲内容相同，不重复列出。
全程使用随包模板，不需要联网加载，不支持本版之外的波形导入、编辑或自动更新。来源及原仓库使用声明见 _internal/docs/waveform_sources.md。

## 4. 不开游戏／不连接设备怎么测试

“仅测试识别”使用同一画面识别与反馈合成逻辑，但不连接 APP。可全屏显示已有游戏截图，保持与游戏相同的分辨率、完整画面位置及比例；F8 启用后观察血量和会话日志。随意缩放或在普通图片窗口留边会让血条位置变化。

单张静止图只能检查该血量读取；测试受伤、治疗或死亡需要按时间依次显示已知状态：满血→掉血、低于所选门槛保持（默认 75%）、回血、正血→零。门槛 0% 时不应出现残血持续层，但其他事件仍可输出。初次有效画面用于建立基线，不触发凭空伤害或治疗。
连接 APP 后用相同步骤观察对应通道的强度和波形。仅 A 应只有 A 非零，仅 B 应只有 B 非零，双通道可设置不同强度观察两路。APP 支持无设备模式时不需要实体设备。

## 5. 扫码失败与防火墙

新版主窗口提供“连接权限”：先停止全部，再打开窗口并点击“一键配置连接权限”，确认提示后在 Windows 管理员授权窗口点击“是”（标准用户可能需要管理员凭据）。取消授权不执行本次修改，之后可重试。普通启动、打开权限窗口与“刷新状态”不会自动修改防火墙。

按钮仅为当前完整包的 node.exe 创建专用网络、本地子网 TCP 入站规则。后端使用动态端口，规则按本包程序路径匹配；不为所有程序开放端口、不关闭防火墙、不开放公用网络、不自动改变网络类型。更新时保持安装位置不变，通常可复用规则；移动目录后需在新目录配置。受组织策略限制、存在其他拦截规则、当前使用公用网络、访客隔离或局域网故障时，规则已配置仍不等于手机一定可达。

“撤销本程序规则”只删除该按钮为当前路径创建的规则；不删除 Windows 弹窗或你手动添加的规则，也不清理其他安装目录的规则。所以撤销成功不等于所有 APP 连接必然被阻断。同名规则不属于本按钮时会拒绝覆盖／删除。配置和撤销仅限停止状态，F8 暂停仍不解锁。

完成后窗口会重新读取规则状态。若显示超时、读取失败、未取得管理员权限或策略受限，不能当作成功；请刷新状态或使用下面的手动排查方式。无需始终以管理员身份运行主程序。

电脑和手机应在同一可信局域网。二维码使用电脑的 IP，不是手机的 IP。自动检测到 IP 不等于手机一定能连到电脑；访客网络隔离、VPN 或防火墙都可能阻止连接。

Windows 放行对象是本包的 _internal\\runtime\\node.exe，不是游戏本体、其他 Node 安装或只有主 EXE。软件内指南顶部会显示当前后端的完整路径，可选中文字复制。

需要放行时，由用户打开 Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙 → 更改设置 → 允许其他应用 → 浏览，选择上述实际 node.exe。只允许自己信任的“专用”网络，不关闭整个防火墙、不做路由器公网端口映射。软件不会自动修改这些设置。

2026-09-14 的上一版手机配对故障，在放行该内置后端后成功连接，用户报告 APP 出现波形。这是上一版的现场结果，不替代新版测试。移动软件目录会改变后端路径，可能需要重新放行新的路径。

二维码超时或 APP 断开：停止全部后重新连接，扫描新码。不要扫描截图中的旧码。日志在 EXE 旁 sessions 的最新会话目录；其中 config.ini 是该次设置快照，runner.log 和 trigger.jsonl 用于排查。

## 6. 升级与回退

保留现在能用的旧版压缩包和软件目录。升级前先停止全部、关闭旧版，确认其后端已退出。
为保持已经放行的后端路径，可以先备份整个旧安装目录，然后将新版完整文件解压覆盖到相同位置；不要只更新 EXE。保留原 feedback_settings.ini、hud_settings.ini 和 sessions，新包不附带你的私人设置或历史日志。若改用新目录，需核对该目录的 node.exe 防火墙规则。

本次 HUD 包在独立目录提供，现有可用版本不会自动被覆盖。需要沿用已放行的路径时，先关闭所有旧会话并备份，确认新版可启动后再按上述流程更新。首次未保存 HUD 档位继续使用旧版兼容预设，主动选择并保存后才启用新档位。回退时保留一份 hud_settings.ini，使用完整旧版目录；旧版不读取新 HUD 设置。

回退前同样关闭程序，再使用完整旧版备份；不要混合不同版本的 EXE 与 _internal。回退到不支持自定义门槛的旧版时，必须同时恢复升级前的 feedback_settings.ini：旧版严格校验会拒绝新 [trigger] 段，不能只换旧 EXE。先另存新版设置及新增会话，再恢复旧完整包和对应旧设置；日志不应删除。每个新包的自动测试、模拟 APP 测试和真实手机 APP 测试分别记录。
