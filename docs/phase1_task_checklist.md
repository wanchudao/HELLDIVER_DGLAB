> 用途：把 Phase 1 执行计划进一步拆成可以逐项推进、逐项验收的任务清单。

---

## 1. 使用方式

- 本文档是执行层 checklist，不替代设计文档
- 每个阶段都按以下顺序推进：
  1. 阅读目标与完成标准
  2. 完成准备项
  3. 按顺序执行任务
  4. 做阶段验收
  5. 记录遗留问题后再进入下一阶段
- 若阶段验收失败，不进入下一个阶段

## 2. 总体原则

- 先离线，后实时
- 先正确，后性能
- 先视觉，后设备
- 所有阈值优先收口到 `config.ini`
- `unknown` 永远不能触发设备事件
- 不在评估口径不可信的前提下调算法

## 5. Phase 2：血量检测修复

### 5.1 阶段目标

- 修复 `health_detector` 在红屏和治疗场景下普遍误读 `100%` 的问题

### 5.2 主要文件

- `src/health_detector.py`
- `config.ini`

### 5.3 准备项

- [ ] 基于 Phase 1 输出确认四类样本的实际误判模式
- [ ] 明确当前 `filled_score` 的错误来源
- [ ] 确认是否保留当前 `Lab` 作为默认色彩空间

### 5.4 实施任务：正确率优先

- [ ] 审查 `p90_luma / redness / texture / gradient` 四类特征的实际作用
- [ ] 重新定义 `redness` 在 `filled_score` 中的方向和权重
- [ ] 保持 `luma` 为主特征
- [ ] 增强 `texture / gradient` 对空槽斜纹的区分作用
- [ ] 如有必要，新增“相对亮度”或“最亮列差值”特征
- [ ] 对列分数增加轻量平滑
- [ ] 重新检查全空、全满、极低血量的边界处理
- [ ] 让 `_find_boundary()` 使用 `cap_ignore_left/right`
- [ ] 重新审视 `confidence` 计算是否仍合理

### 5.5 实施任务：调参与验证

- [ ] 调整 `config.ini` 中 `features` 相关参数
- [ ] 针对 `full_health` 回归验证，确认不被误伤
- [ ] 针对 `injured` 验证是否能稳定低于 `75%`
- [ ] 针对 `death` 验证是否能接近 `0%`
- [ ] 针对 `healing` 验证是否不再普遍读成 `100%`
- [ ] 记录每轮调参前后的基线变化

### 5.6 阶段验收

- [ ] 满血样本多数读到 `95%-100%`
- [ ] 受伤样本多数明显低于 `75%`
- [ ] 死亡样本多数接近 `0%`
- [ ] 治疗低血样本不再系统性误报为满血
- [ ] 血量检测结果已具备进入状态机调试的基础

### 5.7 本阶段交付物

- [ ] 修复后的 `health_detector`
- [ ] 一版可复现的 `config.ini` 参数组合
- [ ] 调参结果摘要
