# Beta 2／DGHub 1.0.6：新版测试与回退

本次只交付新的完整软件包，不会自动升级你的安装。独立版直接运行；DGHub 版由宿主导入启动，不要把两种 ZIP 混用，也不要同时开启输出。

## 先备份，再开始

独立版先点停止全部并退出，保存完整旧目录和旧 ZIP，尤其是 feedback_settings.ini、hud_settings.ini、ui_settings.ini、sessions 和日志。新包解压到单独目录可直接测试，但不会自动继承旧设置。

DGHub 先停用旧插件，备份完整旧包、宿主中的该插件配置及会话数据。导入完整 1.0.6 ZIP，确认配置页版本为 1.0.6。不要只复制 EXE，不需要另装 Python、Node、OpenCV 或抓屏库；DGHub 1.9.7／SDK v1 及其 APP、设备连接仍由你自己的宿主管理。

游戏画面保持完整 1920×1080，软件选择游戏相同 HUD 档位（0.75–1.25、每档 0.05）。可以先用 CHECK／截图检查读取原始截图，不连接设备；单图只能检查定位和单帧血量，不能测试死亡模式。

## 三个死亡模式怎么测试

独立版：停止全部 → 反馈设置 → 死亡反馈模式 → 保存 → 开始新会话。

DGHub：停用插件 → 死亡配置区选择死亡反馈模式 → 启用。运行中改动只是待生效，F8 暂停再恢复不会应用新设置。

1. **定时反馈**：保留原默认，确认一次从正血到零后默认 5 秒结束。初次画面已经为零不能触发。
2. **持续至复活**：确认死亡后，零血有效 HUD 期间持续；复活并重新确认正血后死亡层结束。治疗等其他反馈可能仍在运行，这不等于死亡没退出。
3. **一次也不能死**：确认死亡后持续；复活不解除，面板显示挑战已触发。点击按钮暂停只停止输出，恢复会恢复惩罚。第一次 F8 清除挑战并保持暂停；第二次 F8 才开始。结束整个会话也会清除标记。

先用“仅测试识别”／DGHub 未连接设备的 VISION ONLY 检查血量、标记和启停。无设备时 DGHub 实际 A/B 请求为 0，不把逻辑状态当作设备反馈。若要测真实 APP／设备，再从低强度和低上限开始，先确认暂停／停止。

菜单遮挡或没有 HUD 时应该显示 NO HUD／HP -- 并停止输出，不应该假死。有效画面恢复首帧只建立基线，不产生虚假治疗。抓屏异常、失帧或断线后应保持暂停；不会自己恢复。没有新增观战／增援动画／结算识别。

## DGHub 直播按钮怎么测试

配置中的控制面板选择“直播模式（极简按钮）”，停用后重新启用。顶部中央只留下小按钮，没有 HP、强度、日志或动画。

- 悬停不弹出、不展开、不启停。
- 单击只展开完整控制面板，不能顺便开始反馈。
- 点击完整面板的 LIVE BUTTON [-] 收回小按钮，识别和挑战状态不变。
- 拖动小按钮应移动而不是展开；位置保持在所选屏幕工作区内。
- 游戏里检查悬停、展开、收回、拖动没有抢焦点，F8 仍可暂停／重置。
- F8 冲突时应暂停并显示完整面板和 F8 UNAVAILABLE，仍有鼠标暂停／退出入口。

这个“直播模式”只精简本插件窗口，不接入弹幕／礼物，不隐藏 DGHub 或事件卡片，也不保证 OBS 等软件不会捕获小按钮。独立版不增加此按钮，继续使用灵动岛。

## 更新与回退

独立版要保留已经放行的后端路径，应先完整备份，在原安装位置配套更新新 EXE 和整个 _internal，保留个人设置、sessions 和日志；确认指南中的实际 node.exe 路径未变。不要通过删除整个旧目录来升级。新目录连接失败先查网络／地址，再根据需要明确确认连接权限；不要关闭防火墙。

DGHub 同 ID 更新会替换插件程序，宿主设置仍独立保存。备份后再导入；保险“允许输出”不是启动开关，新会话默认暂停，仍需 F8／浮窗开始。

若回退，恢复完整 Beta 1／1.0.5 旧包及升级前对应配置；旧版不认识 death_feedback_mode 和 panel_mode=live。不能只换旧 EXE。保留新版日志供排查，不删除历史。

自动回归、软件模拟协议和隔离原生宿主通过不等于你的游戏／手机／设备已经通过。本次记录包括一次隔离原生启动超时及后续相同版本成功重试，原因尚未证实。若启用再次出现 10 秒接入超时，保存运行日志、版本和操作步骤；不使用重置卡。
