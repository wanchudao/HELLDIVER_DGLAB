# HELLDIVER DGHub 插件使用指南

适用：DGHub 1.9.6、SDK v1、Windows x64。软件包内的 `acceptance/` 保存本次验收证据；软件模拟、原生宿主、真实游戏、手机与实体设备结果必须分别查看，不能把旧版本成功结果当作本版已通过。

## 使用流程

DGHub 负责连接 APP 和设备。插件不带官方 Node 后端、二维码服务或防火墙修改工具，不需要用户另装 Python、Node 或抓屏库。

1. 在 DGHub 插件中心导入完整 ZIP；配置仅在 DGHub 中维护。
2. 游戏完整铺满所选 1920×1080 屏幕。选择显示器编号，并把插件 HUD 大小设为与游戏相同的值。
3. HUD 允许 0.75–1.25，每档 0.05，共 11 档。这里不是分辨率或 Windows 缩放。
4. 选择仅 A、仅 B 或 A+B，并为五种反馈分别选择波形和 A/B 强度。默认仅 A。
5. 宿主本插件的待机强度 `idle_strength` 必须为 0；非零会明确报错，插件不自动改写。“允许输出”只是保险，默认打开；关掉立即暂停并申请双路归零，重新打开不会自动启动。
6. 启用插件时仍为暂停。SDK 握手后约 0.5 秒为旧短租约排空等待，期间不能启动；等待启动检查就绪后，在战场内按 F8 或点击浮窗／灵动岛按钮开始，再次操作暂停。DGHub 中不再提供启动识别按钮。关闭面板退出插件。

导入完整包，不要只复制 EXE：相对入口 `helldiver_dglab.exe` 及 `_internal` 中的运行库必须一起保留。正常运行由 DGHub 提供启动参数，直接双击 EXE 不会绕过宿主连接。软件截图检查和指南不需要设备；实体设备测试前应从低强度开始，先确认暂停和停止行为。

HUD、显示器、波形、强度和通道等改动下次禁用／启用插件生效。F8 暂停不会切换当前会话配置。灵动岛折叠／展开只改外观，不重连、不启停。隐藏面板时 F8 仍可使用。

没有连接设备也可以通过 F8／浮窗开始识别血量；此时显示 VISION ONLY，实际 A/B 请求为 0，不发送波形或非零强度。设备接入、断开或参数变化会暂停并清空基线，重新按 F8 确认后才能继续；不会因后来连上设备而自行输出。保险关闭时 F8 不启动，浮窗会显示保险未打开的原因。

1.0.1 兼容旧配置中的 `running` 字段，但不再把它作为启停命令，也不自动改写／删除历史配置。旧开关状态无论开关，都不会代替本地 F8／浮窗操作；新会话仍默认暂停。仅“允许输出”保险可立即生效，其他设置保留待下次启用生效的规则。

1.0.2 修复 HUD 下拉框保存格式兼容：DGHub 界面可能把 1.00 存为字符串 `"100"`，此前插件错误拒绝而在启动时退出。现在兼容 11 个准确档位的整数／字符串形式，进入识别和会话快照时统一为整数；不会改写你的宿主配置。`"76"`、`"100.0"`、`"1.00"`、空值或带空格的值仍不接受，不会猜测或自动换档。

1.0.3 保留上述启动修复，并修正正常停用的记录：DGHub 发送停止通知后会立即正常关闭连接，不等待插件的归零／状态回复。插件先停止本地识别和全部续发、尝试双路归零，再把已收到停止通知后的正常关闭记录为正常结束。未经停止通知的断线、异常关闭、超时和其他发送失败仍报错，不自动重连；正常退出不是设备收到归零或波形缓存清空的确认。

1.0.4 将 F8 从瞬时键位轮询改为 Windows 全局快捷键消息，减少短按漏检，长按不反复切换。只注册 F8，不监听其他按键，不注入游戏或修改系统设置；退出时释放注册。若 F8 已被其他程序占用或监听失败，插件明确显示 `F8 UNAVAILABLE` 并暂停，仍可通过浮窗按钮操作；隐藏模式会显示完整面板作为备用入口。恢复快捷键需先排除冲突，再停用／启用插件，不会自动重注册或自动恢复输出。

## HUD 证据与截图检查

0.75、0.80、0.85、0.90、0.95、1.00、1.25 有满血实拍。1.05、1.10、1.15、1.20 为插值推算，合成测试不等于真实游戏验收。

正式运行的数据独立存于 `%LOCALAPPDATA%\HELLDIVER_DGLAB\DGHub\helldiver_dglab-<安装路径标识>\sessions\`。DGHub 同 ID 导入会替换程序目录，外置记录因此不随程序升级删除；同一路径升级使用同一数据位置，不同安装互不覆盖。GUIDE 顶部和 SDK 的 `session_record.directory` 显示实际位置。软件验收模式只在专属测试目录保存，不写真实用户数据目录。

每次运行新建独立会话，不覆盖历史或独立版设置。`config_snapshot.json` 记录实际生效的 HUD 档位、完整 ROI、来源及反馈配置；待生效修改不改写这份快照。`trigger_log.jsonl` 为该次识别／反馈诊断记录，`session.json` 标记运行与收尾状态、丢弃行数和输入来源；不保存 DGHub token。日志采用有界后台队列，磁盘阻塞不等待控制线程，停止请求发送后才作有限时长的日志收尾。异常强杀或磁盘故障留下 `running`／不完整记录时，不能当成正常结束通过。

错误档位、HUD 遮挡／丢失、非 1920×1080 或抓屏异常不会当作死亡；显示 NO HUD / HP --，清除反馈请求及血量基线。有效画面恢复后重新建立基线，不伪造回血。

暂停后点 CHECK 选择本地原图。截图工具独立运行，不连接 DGHub、APP 或设备。它展示图片尺寸、原始血量、端帽／测量框和拒识原因。单图不验证受伤、治疗或死亡事件；局部放大仅供观看，识别不缩放原图。

GUIDE 打开本指南；展开灵动岛可找到 CHECK、GUIDE。指南窗口不会阻塞识别与 F8 控制循环。

## 五类反馈

1.0.5 新增“残血／濒死触发血量 %”：0–100 整数、步长 1，默认 75。确认有效基线后，0＜有效原始血量＜门槛时持续反馈；等于门槛退出该层，100% 不在满血时触发。0% 只关闭残血层，不改变受伤、治疗或死亡，也不清空 A/B 数值。门槛不是输出强度，A/B 共用一个门槛。运行中修改仅待生效，F8 暂停再恢复仍用当前会话值，停用再启用才应用。SDK 状态与 config_snapshot.json 记录实际已应用值。

缺此字段的旧配置默认 75%；非法值报错，不静默取整。升级前备份旧完整插件及对应宿主配置。回退到 1.0.4 时必须同时恢复旧配置，因为旧版会拒绝新增 low_health_threshold_percent 字段；不要只换旧 EXE 或直接导入旧 ZIP 后留下新字段。用户原有波形、强度和历史会话须保留。

| 反馈 | 规则 | DGHub 默认波形 | 默认 A/B 基准 |
|---|---|---|---|
| 受伤 | 0.2 秒内累计下降，强度随累计伤害量变化；反馈默认 2 秒 | 连击 | 20% / 20% |
| 残血／濒死 | 默认 0 < HP < 75% 时持续；门槛可调，0% 关闭 | 呼吸 | 10% / 10% |
| 治疗确认 | 有效回血触发确认脉冲，默认 2 秒 | 潮汐 | 15% / 15% |
| 治疗舒缓 | 回血期间持续，最近回血后默认保持 2 秒 | 心跳节奏 | 5% / 5% |
| 死亡 | 连续有效正血到零，每条生命一次，默认 5 秒 | CS2-死亡 | 40% / 40% |

舒缓与死亡的这两个默认预设不同于独立主版的专用模板，可在 DGHub 分别修改。复活的连续有效回血沿用治疗，不新增击杀、换弹等无法可靠识别的事件。

波形优先级为死亡 > 治疗确认 > 受伤 > 治疗舒缓 > 残血。死亡清除其他反馈；其余有效强度叠加并受各通道独立上限约束。零贡献事件不抢占波形；某一路为零只停止该路。双通道共享优先波形与事件节奏，但强度独立。

## 强度与故障排查

界面的 A/B 数值是本插件请求的百分比，不是设备原始刻度，也不是 APP 一定显示的值。设备上限由 DGHub 管理；多插件在每通道取最大层，不累加。停止本插件不代表其他插件或设备整体强度必为零。

强度改变立即提交；持续有效反馈每路每 0.10 秒续发一个 0.30 秒 `rollback` 请求。某路降到零立即申请该路归零，停止其续发；暂停、无 HUD、失帧或退出停止两路续发并申请两路归零。正常发送失败会停止整个插件，不静默改成单路工作。

SDK v1 的强度 `trigger` 续发会产生宿主事件卡片，并可能触发 DGHub 的高强度音效；这是本次采用短时自动回退策略的已知行为。插件不发送未知的静音字段，也不自动关闭 DGHub 全局卡片或音效设置。若不想显示或播放，可自行查看 DGHub 对应设置，但这不会改变插件发送策略。

固定波形按完整模板周期播放，强度续发不会每 0.25 秒重新播放模板开头。有限事件的末段按剩余时长截断；随机预设使用至多 1 秒的播放窗口。双通道共用波形节奏，但独立计算和限制强度。预设库在会话启动时读取一次；运行中不要修改当前正在使用的预设。

这里的“暂停／停止”指停止本插件续发并清零本插件强度层，**不是设备波形缓存清空确认**。SDK v1 没有本插件可调用并验证的缓存清空确认接口；缓存中的波形可能残留，其他插件接管时也不能把本插件归零理解为设备完全清空。自动回退由宿主从其实际接受的最后一次请求计时，还会受调度、路由和队列影响，不能把 0.30 秒写成设备端绝对停止上界。断网、插件冻结或异常终止的回退以包内本轮原生实测记录为准。

等待 HUD：确认选择的显示器和游戏 HUD 档位，完整 1920×1080、未被菜单遮挡。先用原始截图检查定位，再进行游戏内抓屏验收。

配置非法：核对整数强度 0–100、合法档位、实际存在的波形预设和待机强度 0。遇到历史非零 `idle_strength`，先停用插件，在 DGHub 中明确修改为 0，再重新启用；插件不会静默迁移配置，也不会声称这一步清除了设备缓存。

入口会在 SDK 握手前读取 DGHub 1.9.6 的只读 Coyote 波形目录，以启动快照校验五项预设名称、格式、帧数与随机标记。只访问宿主启动参数指定的本机地址，不扫描端口、不获取 token、不改预设；接口不可用、响应不兼容或所选名称不存在时不启动输出。这是按已核对的 1.9.6 Web API 接入，不是 SDK v1 能力协商。宿主运行中新增／删除／修改预设没有原子性保证；请先停止插件，再修改库和设置并重新启用，建立新的目录快照。目录校验通过不等于真实设备播放或停止已经验收。

插件断线：保持暂停，排查 DGHub 日志并禁用／重新启用插件；不自动续接输出。扫码、局域网和 APP 连接问题由 DGHub 排查，本插件不改系统设置。

升级前先禁用插件，备份 DGHub 插件包、该插件配置和上面的会话数据目录。当前宿主将插件配置保存在程序包目录之外；同 ID 更新会替换包内文件，但本插件不会在升级时重置已保存的设置。不要同时启用旧版和新版；独立主版与其设置、日志不被本插件覆盖。回退需使用原完整包及对应配置，不把开发目录复制到 DGHub 内部运行库。迁移到其他安装路径时数据标识会改变，应保留原数据备份；本插件不静默搬移旧日志。

若之前启用过使用未知或较长租约的开发预览，升级前应停用旧插件并重启 DGHub，再导入新包。新版本 0.5 秒排空等待仅针对自身 0.30 秒短租约，不保证清除旧预览的任意长任务；插件不会自动重启宿主或改写其他插件设置。

推荐首次检查：导入包并确认启动暂停 → 选择与游戏相同 HUD 档位 → CHECK 检查原图 → 仅 A、低上限启动 → F8 暂停检查本插件层归零 → 再分别验证仅 B 和双通道。游戏内另测 HUD 消失、受伤、回血与死亡；手机 APP 能连接并不代表所有事件、路由故障和实体设备均已通过。
