## 1. 已知事实（经 TRAE Work 视觉分析验证）

### 血条 ROI
- 坐标：**(97, 943) - (307, 967)像素**
- 跨四种状态（满血/受伤/死亡/治疗）位置**完全一致**
- 主条本体：(105, 949) - (299, 958)，宽约 194px，高约 9px

### 四种状态的血条特征

| 状态 | 血量 | 血条颜色 | 全屏滤镜 | 特殊信号 |
|------|------|----------|----------|----------|
| 满血 | ~100% | 近白 RGB(220,218,198) | 无 | — |
| 受伤 | ~45-48% | 粉红红 RGB(125,50,48)，左亮右暗 | 红色 | — |
| 死亡 | ~0% | 全暗红 RGB(132,77,72)，无亮填充 | 红色极浓 | 阵亡文字 + 骷髅图标 |
| 治疗 | ~3-8% | 少量亮残余 + 大面积暗红 | 青蓝色 | 注射动作 + 刺激剂数量 |

### 消耗方向
- **从右往左消耗**，剩余血量始终在左侧
- 治疗时从左往右恢复

## 2. 算法架构

### 主流程

```
屏幕截图 (1920x1080)
    │
    ├─ ① 血条 ROI 裁剪 → (97,943)-(307,967)
    │   ├─ 逐列检测"有效血量像素"
    │   ├─ 计算填充百分比
    │   └─ 判断整体颜色特征
    │
    ├─ ② 全屏边缘采样
    │   ├─ 红色通道占比
    │   └─ 青蓝色调检测
    │
    ├─ ③ 状态判定（单帧）
    │   ├─ 血量 ≈ 0% → 死亡
    │   ├─ 血量 < 75% + 红色滤镜 → 受伤
    │   ├─ 青蓝滤镜 + 血量回升 → 治疗
    │   └─ 血量 ≈ 100% + 无滤镜 → 满血
    │
    └─ ④ 事件检测（跨帧，状态机）
        ├─ 血量突降 → 受伤脉冲（0.2s 窗口合并）
        ├─ 血量归零 → 死亡事件
        ├─ 血量回升 → 治疗事件
        └─ 血量 < 75% 持续 → 残血持续刺激
```

## 3. 核心问题：纯像素方案的风险

### 3.1 ROI 位置可靠性
- **现状**：4 张截图 ROI 完全一致
- **风险**：不同分辨率、画面模式（全屏/窗口）、HUD 缩放设置下可能偏移
- **对策**：预留 ROI 参数为可配置，必要时手动校准

### 3.2 颜色检测可靠性
- **现状**：满血近白、受伤粉红红、死亡全暗红
- **风险**：全屏红色滤镜会污染血条颜色，可能导致：
  - 满血在红屏下被误判为受伤
  - 轻微受伤在滤镜下被误判为死亡
- **对策**：不能只看血条内像素颜色，必须结合**血条内外对比** + **全屏滤镜强度**

### 3.3 样本量不足
- **现状**：每状态仅 1 张截图
- **风险**：单一帧可能不代表该状态全貌
- **对策**：需要更多截图覆盖不同血量值（10%/25%/50%/75%）

## 4. 方案选择

### 方案 A：纯像素分析（轻量方案）

- 原理：固定 ROI 逐列像素扫描
- 优点：零依赖、极快、无需训练
- 风险：对 HUD 位置变化和强烈滤镜敏感
- 适用：分辨率固定、HUD 位置不变的单人游戏环境

### 方案 B：YOLO 定位 + 像素分析（混合方案）

- 原理：YOLO 检测血条区域（自适应位置）+ 像素分析读血量
- 优点：位置鲁棒
- 风险：需采集标注数据、速度较慢、YOLO 本身也会受滤镜干扰
- 适用：HUD 位置不固定或多分辨率场景

### 方案 C：模板匹配 + 像素分析

- 原理：用满血血条模板做匹配定位 + 像素分析读血量
- 优点：比 YOLO 轻量
- 风险：模板在非满血状态下可能匹配失败
- 适用：HUD 位置固定的单人游戏

---

## 5. 推荐路径

**Phase 1：用方案 A（纯像素）做出 MVP，验证核心链路**
- 最快出结果
- 用现有 4 张截图 + 你继续提供的截图逐步验证
- 如果方案 A 不可靠，再切换到方案 B

**Phase 2（如需要）：根据方案 A 的弱点补强**
- ROI 偏移严重 → 加模板匹配或 YOLO 定位
- 颜色误判严重 → 引入 HSV 色彩空间 + 自适应阈值
