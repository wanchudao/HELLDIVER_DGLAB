# Beta 3／DGHub 1.0.7：多分辨率测试与回退

这次增加的是实验性推算适配，不是已经完成真实 2K／4K 游戏验收。完整 ZIP 包含运行库，不需要额外安装 Python、Node、OpenCV 或抓屏组件；插件仍需 DGHub 1.9.7／SDK v1。两版不要同时输出。

## 新增了什么

1920×1080 保持原配置。2560×1440 从对应 1080p 档位乘 4/3，3840×2160 乘 2；各自保留 HUD 0.75–1.25、每档 0.05、共 11 档。位置、血槽尺寸、端帽、采样带和几何容差同步调整，颜色／HP／反馈规则不变。

高分辨率全部标为推算，实验开关默认关闭。没有自动选 HUD、任意框选、任意分辨率或 HDR 适配；游戏应完整铺满所选屏幕。分辨率按实际抓屏像素读取，不按 Windows 字体缩放或游戏菜单猜测。

## 独立版怎么测

1. 停止并退出旧版，备份旧完整目录、个人设置和日志；新包先解压到独立目录，运行 HELLDIVER_Main.exe。
2. 选择游戏所在屏幕。在 HUD 设置中选择游戏相同档位；如果是 1440p／4K，主动勾选“允许实验性 2K／4K 适配”并保存。旧版兼容预设不能当成高分辨率 HUD 1.00。
3. 先用截图检查选择原始截图，检查实际尺寸、端帽、测量框与血量。此步骤不启动后端，不连接 APP，也不测试连续事件。
4. 点仅测试识别，进战场后按 F8，观察 HP 和 NO HUD。遮挡 HUD 应停止并清空基线；恢复时不能伪造回血或死亡。
5. 再连接官方 APP，扫码后按 F8，从低强度／低上限检查受伤、治疗、死亡、暂停和停止。软件输出不等于实体设备读回。

设置只能停止全部后修改，F8 暂停不解锁。未勾选实验开关时，高分辨率实时会话会明确拒绝启动；截图检查仍可预览推算配置。运行中变更分辨率后需停止并重开，不自动切换。

## DGHub 怎么测

先停用旧插件并备份其完整旧包、对应宿主配置和会话记录，再导入完整 1.0.7 ZIP。配置正确的显示器、HUD 档位及实验开关；开启插件，等待抓屏和配置就绪，再用 F8／浮窗开始。没有设备时可以 VISION ONLY 检查，但实际 A/B 请求为零。

实验开关、HUD、波形和强度的修改仅在停用后重新启用生效；保险开关仍按原规则即时暂停，不自动恢复。灵动岛和直播小按钮行为不变。SDK 的本插件层归零不是整个设备归零或波形缓存清空确认。

## 死亡模式与停止

保留定时反馈、持续至复活、一次也不能死。挑战触发后第一次 F8 清除挑战并保持暂停，第二次才开始；鼠标暂停不清除挑战。无 HUD 停止输出但保留已确认的持续死亡标记，恢复首帧重建基线。失帧、抓屏异常、断线或发送失败保持暂停，不自动恢复。

## 更新与回退

新包没有替你安装或覆盖旧版。独立版若要保持已放行的后端路径，先备份原目录，在原位置配套更新 EXE 与完整 _internal，保留 settings、sessions 和日志；不要删除整个旧目录。确认指南显示的 node.exe 路径与原来一致。换目录连接失败不一定是权限问题，不要关闭防火墙。

回退独立版 Beta 2，恢复完整旧包和升级前 hud_settings.ini；旧版不认识 schema 2。回退 DGHub 1.0.6，恢复完整旧插件及对应旧宿主配置；旧版不认识 allow_experimental_high_resolution。回退更早版本还要恢复对应死亡模式／门槛配置，不能只换 EXE。

## 验收边界

合成血条、1080p 原图重采样派生素材、软件协议、隔离宿主和真实游戏是不同证据。重采样图片不叫高分辨率实拍；合成处理耗时不叫真实 4K 抓屏帧率。本轮没有新增真实 1440p／4K 显示器、游戏、手机或实体设备验收，也未启用 DSR、修改显示／防火墙设置、使用重置卡或自动上传 GitHub。

若在真实高分辨率下拒识，请保留原始截图并注明尺寸、HUD 档位、显示器编号、窗口模式和 HDR 状态。不要裁剪或缩放后再作为校准素材；程序宁可拒识，也不根据背景亮块猜测血量。
